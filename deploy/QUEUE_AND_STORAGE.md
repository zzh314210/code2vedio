# 制作队列、资源和文件保存

## 运行规则

正式站与预览站共用一个持久队列，一次只制作一条视频。创作、剪辑分析、剪辑导出、成片修改、大纲/分镜 AI 修改和主动 AI 审核都使用该消费者；等待用户确认时让出位置。新用户不会被同一用户连续提交的任务挡在最后：例如 A1、B1、C1、A2。每个账号最多 5 条等待任务，全站最多 30 条等待任务。

管理后台 → 制作队列：查看阶段、等待任务和内存；上移、下移、优先处理、取消尚未开始的任务，或恢复公平排序。调序和取消均留审计记录。用户也能取消自己的等待任务。开始运行的任务不能通过“取消排队”中止，避免不完整输出和已产生费用的歧义。

队列位于 `/data/code2vedio/.runtime/queue.sqlite3`。正式站与预览站使用不同 namespace；任务参数使用各环境 `private/worker.key` 派生的密钥加密。完成、取消或中断后清除任务参数。服务重启后恢复尚未开始的任务；已经开始的任务标记为中断，由用户检查后重试，避免重复调用付费模型。备份队列必须同时保留各环境密钥。

## 资源预算

`code2vedio.slice` 统一包含正式/预览 Go 服务、Python worker、FFmpeg 子进程以及 Docker 渲染容器：

| 资源 | 总上限 |
| --- | --- |
| CPU | 250%，即 2.5 核 |
| 物理内存 | 2 GiB，1800 MiB 开始回收压力控制 |
| 额外 Swap | 4 GiB |
| 同时制作 | 1 条 |

Docker 使用 `--cgroup-parent=code2vedio.slice --cpus=2.5 --memory=2g --memory-swap=6g`；最后一个参数是物理内存和 Swap 的合计。不能只限制 Python 服务，否则 Docker 会逃出项目总预算。现有 Go 子服务的更小上限继续生效。

开始下一条前，检查主机 MemAvailable 至少 768 MiB，且项目内至少有 512 MiB 可用空间；可回收的 inactive file cache 不作为不可用内存。内存不足时保留队列，界面显示“等待可用资源”，恢复后继续。时间估计按任务类型、视频长度及当前步骤给出区间，不是完成承诺。Swap 是缓冲，频繁换页时速度会下降。

sub2api 的运行方式和限额未调整。其 1.6 GiB 是这台机器的容量规划预算，不是本次创建的内存预留；此前实测相关容器合计约 468 MiB，使用量会变化。

部署文件：`code2vedio.slice`、`resource-api.conf`、`resource-worker.conf`。API/worker 的配置分别安装到对应 systemd 服务的 drop-in 目录。预览 worker 的 `C2V_QUEUE_NAMESPACE` 必须为 `preview`，正式为 `production`。先创建 `.runtime`（运行用户所有，0700），再 daemon-reload、在没有运行中任务时重启服务。

## 24 小时保存

用户作品目录使用 UTC 时间戳：`video_projects/users/YYYY-MM-DD/HHMMSS-用户前缀-studio-任务ID/`，剪辑使用 `edit-任务ID`。完成、等待人工确认、失败或取消后保存 24 小时；页面显示剩余保存时间。排队、运行中和仍被排队修改版依赖的原始作品不会被删除。

worker 每 60 秒清理一次过期作品，包含视频、上传原片/素材、配音、中间文件和副本。过期任务保留 7 天轻量状态记录，链接能明确显示“已过期”，不再提供下载。异常中断且未写元数据的上传目录满 24 小时后清理。个人上传 BGM 从上传起保留 24 小时；生成任务使用自己的音乐副本，不受原上传文件到期影响。

首次启用时，历史用户作品从迁移时间起获得 24 小时宽限。默认音乐、声音样本和 `web/public/showcase` 的公开样片永久保留。已审核样片源项目可使用受信的 `.permanent` 标记，或通过样片 JSON / `deliverables/manifest.json` 指定；永久资格不能由用户 API 输入。账号、余额、充值账单和模型扣费记录不随视频清理。

## 验收与回滚

本地检查：`scripts/queue_storage_smoke.py`、`scripts/queue_api_smoke.py`、`scripts/background_music_smoke.py`，以及 Go 接口权限测试。签名接口测试只使用替身模型，不产生外部模型费用。

发布前核对无运行任务，备份账号 SQLite、队列 SQLite、密钥、二进制、网页和旧 Git 代码快照；记录所有公开样片 SHA-256。发布后核对实际 cgroup、Docker 容器归属、管理员/普通用户权限、队列操作、试听、移动布局和样片哈希。

网页回滚可直接恢复旧 dist。完整后端回滚前必须处理或取消等待任务，保留 `.runtime` 与密钥，并确认旧代码是否识别时间戳目录；不能直接关掉队列后丢弃等待任务。被保留策略删除的用户视频无法通过程序回滚恢复。

浏览器目前负责输入、预览和播放；Python/Manim/Docker 渲染仍在服务器完成。浏览器不能直接运行 Docker。当前资源预算与单消费者已经覆盖服务端渲染压力。
