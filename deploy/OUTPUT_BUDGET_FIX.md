## 输出预算

此前动画代码请求两次返回 `finish_reason=length`：每次输出 24,000
Token，其中 reasoning_tokens=24,000，正文为零。输入约 4,428 Token，
并非上下文窗口不足。

正式站和预览站的两个平台内容模型（DeepSeek 1017、Kimi K3）上限已提高到
65,536；视觉模型保持 24,000。保持开启思考、最高强度，不改变密钥、价格、
备用模型或历史用量。失败任务 4ceaa37859ff 的加密配置也已单独提高并记录管理审计。
个人自备 API 的显式设置不自动修改。

最高思考下，使用原失败请求和同一个 DeepSeek 1017 服务实测：

- 输入：4,428 Token。
- 输出：52,860 Token，服务商报告思考 47,021、正文 5,838。
  服务商细分之和与输出总数有 1 Token 差异，计费依据总数。
- 完整返回五镜头 JSON，代码 AST / 运行时 API / 风格约束校验通过。
- 耗时约 503 秒；实测使用运营方已有本地密钥，不扣该用户站内余额。
- 原代码通过完整项目校验，隔离 Docker 渲染约 134 秒成功，视频约 20 秒，
  完整 FFmpeg 解码无报错。本次验证止于动画渲染；未声称已完成原用户作品的
  配音合成或视觉审核，原任务仍可由用户点击重试继续。

输出上限包含思考和正文。上限不代表实际计费量，但平台按上限保守预占。
大输出请求的默认流式总等待时间相应增长，65,536 对应 1,800 秒；
显式 total_timeout 仍优先。

各协议的输出预算耗尽显示中文说明，截断文本不得进入 JSON/渲染，
有上游用量时仍只计量一次。不新增相同预算的自动重试。

重试允许仅提高内容模型输出预算，保留已验证的大纲、分镜和配音。
更换内容模型、思考策略、渲染器或素材仍会触发缓存一致性检查。

维护命令（从项目根目录运行；调整已有任务前确认它未运行）：

```bash
api/bin/frame-api -raise-text-output-limit 65536
api/bin/frame-api -raise-text-output-limit 65536 -output-limit-task TASK_ID
```

前者只提高已启用的平台内容模型，后者只更新指定任务并记录审计。
重复执行不重复更新，不降低已有更大上限。
