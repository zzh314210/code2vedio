## 本项目的落地方式

- `templates/editing.json`：四种模板独立定义观察重点、叙事顺序、选段限制、动效上限和审核要点，并记录版本。
- `src/editing_prompts.py`：将观察、规划、审核分开，每步有明确的输入证据、输出 JSON 和不能完成的行为边界。
- `src/editing.py`：执行原片时间、重复范围、完整语句、总时长及动效限制；所有模板先语义审核，失败后最多修正一次，再交用户确认。
- 普通模板若可用重点不足，可以返回较短方案，但须说明具体素材依据并显示实际时长，让用户在导出前确认；不以加载画面或重复内容硬凑时长。带货仍严格保持 30–120 秒。游戏同一原片的选段必须保持时间先后。
- 导出前按实际选段和字幕再次核对。只有选段、字幕、原始证据、模板版本全部相同才复用通过记录。修改字幕或时间线会重新审核。
- 模型只输出选段数据，不能提供可执行命令。FFmpeg 参数由服务器构造；原声音画保留，横竖比例不同时留边，不裁掉产品、HUD 或价格。

带货模板只讲一件商品，报价及适用条件保持完整；游戏模板关注真实操作及前后结果；纪实模板使用自然镜头，不使用聚焦动效；精华速剪删除重复与空白，保留能理解的主题和完整解释。

## 免费资料搜索

使用 Wikimedia 官方 Action API 搜索及 TextExtracts 正文接口。搜索接口失败时尝试 Wikimedia REST 搜索；只有实际取得正文的文章才出现在结果中。每个用户有自己的全文库与查询缓存；外部连接失败时可使用已有正文，并明确说明来自缓存。

网页改用可重试的 GET 搜索，保留兼容的 POST 接口。列表只返回短摘要，正文按需读取，避免每次搜索传输数篇长文。每条结果都能选择或移除。搜索不调用模型、不消耗模型额度；选作资料后，制作视频的模型分析仍按实际用量计费。

百度百科实测拒绝抓取，未添加；视频站无公开字幕时也不伪装成可读素材。现阶段默认仅展示百科与个人素材库。它适合一般知识查询，不能保证覆盖具体考试题目。

## 质量范围

自动检查涵盖时间线合法性、原声上下文、模板约束及最终视频解码/时长，不等于人工对所有画面和口播的最终审片。语音识别仍可能误听专有名词，页面提供逐段原片预览和字幕校对；模型根据抽样画面判断，无法证明未观察到的细节。示例产品视频是原创演示素材，不是真实直播投放效果证明。
