# 冻结标准、反馈修改和成片放行

新建的视频创作任务默认启用质量门禁；历史任务保持原有配置和交付方式。AI 剪辑管线保留原有审核，不冒充已接入本次创作门禁。

## 执行顺序

1. 生成大纲 → 人工确认（或用户明确选择自动确认）。
2. 生成分镜 → 人工确认。确认的事实、旁白和镜头顺序在制作闭环中保持不变。
3. 验收规划模型读取完整确认稿，为每个镜头制定具体要求；程序额外注入内容一致、可视化清楚、角色与逻辑衔接的固定要求。标准与确认稿哈希绑定并存档，修复不能降低标准。
4. 免费配音、真实时长测量和完整字幕时序。字幕文本必须覆盖全部旁白；超出目标时长不自动重写或截断用户确认稿，有人工审核入口的任务退回分镜确认。
5. 动画代码 → 隔离渲染 → 必要的渲染修复。资源不足等基础设施错误不会触发付费模型修代码。
6. 章节先合成配音及所选字幕，再逐镜头审核。每镜头包含均匀分布的八个位置和用户指定采样间隔；审核批次保留镜头起、中、末及相邻镜头的衔接证据。每条结论必须引用真实的本镜头图片和具体依据，漏项、伪造帧、uncertain 都不能通过。
7. 未通过的章节带着冻结标准和失败证据返回代码生成，只重做有关章节，重新渲染并再次审核。有效章节、语音和已完成的审核批次可复用。
8. 合成候选成片；程序完整解码，检测超过 1 秒的全黑/全白画面、超过 3.5 秒的非规划旁白静音、轨道缺失、时长错误，并从实际字幕轨提取文字核对全部旁白。已经批准的回忆停顿单独处理。
9. 完整成片再由视觉模型密集审核，包括全部旁白、全部字幕、镜头内推进和前后衔接。失败会在总修改上限内回到相关章节；媒体完整性错误先重新合成，配音本身异常则停止并保留报告，避免无效付费修复。
10. 每个章节和完整成片全部通过才将 candidate.mp4 原子改名为 final.mp4。下载接口再次验证视频哈希、确认稿、冻结标准和最终报告，未通过返回 409。

## 配置与费用

模型配置弹窗可分别选择内容生成、视觉审核和验收规划模型。验收规划可沿用内容服务，也可单独填地址、Key、模型。平台模式从管理员配置的文本模型中选择，价格单独冻结为 acceptance 用途，账单中单独标识。

| 设置 | 默认 | 范围 |
| --- | ---: | ---: |
| 规划/结构输出修改 | 2 | 0–5 |
| 动画代码结构修改 | 2 | 0–5 |
| 每章节渲染修复 | 2 | 0–5 |
| 每章节画面修改 | 1 | 0–5 |
| 完整成片回修 | 1 | 0–5 |
| 单片模型调用总上限 | 60 | 1–120 |
| 常规采样间隔 | 2 秒 | 0.5–3 秒 |
| 单片平台金额上限 | 10 元 | 0–1000 元，0 不设金额上限 |

次数为第一次尝试以外的自动修正，按环节及目标持久化累计。结构输出错误、备用模型尝试及最终回修也受模型调用总上限约束，SDK 隐藏重试关闭。文件锁防止多入口丢失计数，刷新和重试不重置预算。新建明确的新任务/新版本拥有新预算；用户不能通过重试同一任务续费绕过本次上限。

平台金额准入在 SQLite 事务中检查本任务已结算金额 + 所有待结算预占 + 新调用最坏预占；并发无法超额预占。重试和失败调用按上游实际用量结算，失败并不表示上游免费。无完整用量的预占留待核对，不当成零费用。

自备 API 不要求预付、不扣本站余额、不进入本站模型用量流水。仍有任务调用计数与修改次数保护；实际费用向用户的服务商结算，本站不能承诺第三方金额硬上限。

预估随所选三类模型价格、视频长度、采样密度、修改上限和总调用限制变化；属于估算，不是固定报价。3 分钟、多镜头或高密度设置可能需要提高调用总上限，面板会提醒预估调用数超过当前限制。

## 字幕与用户入口

采用现有 FFmpeg 与开源 [libass](https://github.com/libass/libass)，无额外模型、付费服务或识别依赖。默认烧录在画面下方安全区，中文字体、浅色字与深色描边、最多双行；同时保留字幕轨。关闭字幕后不烧录、不提供字幕轨及播放地址；内部仍保留完整逐句时序用于验收。旧任务的软字幕模式保持兼容。

创作面板“时长与配音”内有字幕开关和“质量门禁与自动修改上限”入口；模型弹窗设置持久保存在账号中。任务冻结自己的设置，之后修改账号配置不影响已有任务。预览区“查看质量验收”显示冻结标准、调用/修改计数、失败原因和画面时间证据。开放 API 的配置和 report 接口与面板一致。

## 边界

完整解码与声音/字幕核对覆盖全片。语义检查是密集图片序列而非逐帧语义理解，模型仍可能误判或遗漏；不能据此承诺绝对正确。普通装饰动效不应被擅自扩成阻断标准，必要教学动态没有足够证据会保持不确定并阻断。已确认稿件不是外部事实真值，真假话模板仍使用独立的可执行逻辑证明，模型不能改写证明。

验收标准、逐批证据、技术检测日志和预算均保存在用户项目 output/quality；按作品原有 24 小时存储周期清理。平台财务记录独立保留，公开样片保持永久存储。

## 验证

- `api/quality_test.go`：并发费用硬上限、已结算/预占累计、独立验收价格、自备 API 不入账、修改和密度对估算的影响。
- `scripts/quality_harness_smoke.py`：完整旁白/字幕、伪造证据和遗漏拒绝、不确定阻断、哈希及规划绑定、持久/并发调用上限；真实 FFmpeg 黑白屏、静音、下方字幕和关闭字幕。
- `scripts/quality_loop_smoke.py`：真实编解码，最终验收失败 → 只改代码 → 重渲染/合成 → 再验收 → 放行；确认稿不变，重试不重置次数。模型为受控测试替身，不能当成真实语义质量证明。
- `scripts/quality_api_smoke.py`：未通过不可下载、报告按用户隔离、历史作品兼容、关闭字幕不暴露播放字幕。
- 真实模型验证过程与结果见本次发布记录；测试输出在 `.tmp/quality-validation/`，未修改或扣费到用户原任务。
